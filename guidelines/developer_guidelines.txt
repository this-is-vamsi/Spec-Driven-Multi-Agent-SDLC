## 1. TECHNOLOGY STACK

- **Primary Language**: Python 3.11+
- **API Framework**: FastAPI (latest stable)
- **ORM**: SQLAlchemy 2.0 (sync session for simplicity in stubs)
- **Database (Dev/Test)**: SQLite (file-based, zero config)
- **Database (Production)**: PostgreSQL 15+
- **Validation**: Pydantic v2 (BaseModel, model_validator)
- **Authentication**: JWT via python-jose, passwords via passlib[bcrypt]
- **API Documentation**: OpenAPI 3.0 (auto-generated by FastAPI)

## 2. PROJECT STRUCTURE

Every generated project MUST follow this layout:

```
project_name/
├── app/
│   ├── __init__.py
│   ├── main.py              # FastAPI app, CORS, router includes, /health
│   ├── config.py            # pydantic-settings for env vars
│   ├── database.py          # SQLAlchemy engine + SessionLocal
│   ├── dependencies.py      # get_db, get_current_user
│   ├── models/
│   │   ├── __init__.py
│   │   └── <entity>.py      # SQLAlchemy ORM models
│   ├── schemas/
│   │   ├── __init__.py
│   │   └── <entity>.py      # Pydantic Create/Update/Response schemas
│   ├── routes/
│   │   ├── __init__.py
│   │   └── <entity>.py      # APIRouter handlers
│   ├── services/
│   │   ├── __init__.py
│   │   └── <entity>.py      # Business logic (called by routes)
│   └── middleware/
│       ├── __init__.py
│       └── error_handler.py  # Global exception handler
├── requirements.txt
└── README.md
```

## 3. API DESIGN STANDARDS

### 3.1 URL Convention
- Lowercase with hyphens: `/api/v1/user-profiles`
- Always version: `/api/v1/...`
- Plural nouns: `/products`, `/orders`
- Nested relationships: `/customers/{id}/orders`

### 3.2 HTTP Methods & Status Codes
| Method  | Purpose               | Success Code |
|---------|-----------------------|-------------|
| GET     | Retrieve              | 200         |
| POST    | Create                | 201         |
| PUT     | Full update           | 200         |
| PATCH   | Partial update        | 200         |
| DELETE  | Remove                | 204         |

Error codes: 400 (bad request), 401 (unauthorized), 403 (forbidden),
404 (not found), 409 (conflict), 422 (unprocessable), 500 (server error).

### 3.3 Response Envelope
ALL responses MUST use this envelope:
```json
{
    "success": true,
    "message": "Operation completed successfully",
    "data": { ... },
    "meta": { "page": 1, "per_page": 20, "total": 100 }
}
```

Error envelope:
```json
{
    "success": false,
    "message": "Validation error",
    "errors": [{"field": "email", "message": "Invalid email format"}]
}
```

## 4. DATABASE STANDARDS

### 4.1 Model Requirements
- All models MUST have: `id` (INTEGER PRIMARY KEY), `created_at`, `updated_at`
- Use snake_case for table names (plural): `products`, `order_items`
- Column names in snake_case: `first_name`, `stock_quantity`
- Foreign keys: `<table_singular>_id` (e.g., `customer_id`)
- Index frequently queried columns

### 4.2 SQLAlchemy Patterns
- Use `declarative_base()` with `Base`
- Session via `SessionLocal` with `yield` in FastAPI dependency
- Always close sessions in `finally` blocks

## 5. AUTHENTICATION & AUTHORIZATION

### 5.1 JWT Configuration
- Access token expiry: 30 minutes
- Algorithm: HS256
- Header: `Authorization: Bearer <token>`
- Secret key from environment variable

### 5.2 Auth Endpoints (when auth is required)
- POST `/api/v1/auth/register` — User registration
- POST `/api/v1/auth/login` — Returns JWT
- POST `/api/v1/auth/refresh` — Refresh token

### 5.3 Protected Routes
- Use FastAPI `Depends(get_current_user)` for auth
- Role-based access via dependency injection

## 6. CODE QUALITY

- Type hints on all function signatures
- Docstrings for public methods
- Use `HTTPException` with proper status codes
- No hardcoded secrets — always from config/env
- Use Pydantic field validators for input validation
- Keep route handlers thin — business logic in services

## 7. LOGGING & ERROR HANDLING

- Structured JSON logging via `logging` module
- Global exception handler middleware
- Log all requests with correlation ID
- Never log passwords, tokens, or PII
- Return generic error messages to client, detailed logs server-side

## 8. SECURITY

- Input validation on all endpoints (Pydantic enforces this)
- Parameterized queries only (SQLAlchemy handles this)
- Rate limiting on auth endpoints
- CORS: configure allowed origins
- HTTPS in production
- No secrets in code or version control
